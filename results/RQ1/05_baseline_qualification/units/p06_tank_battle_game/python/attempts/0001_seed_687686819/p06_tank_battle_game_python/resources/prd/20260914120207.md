## Domain Reasoning

- Core entities and values: Direction, Rect (immutable), Obstacle, Arena, Tank, Projectile, Command subclasses, ScoreBoard, and Game.
- Direction is a strict Enum defined with from enum import Enum, class Direction(Enum):, members N=(0,-1), E=(1,0), S=(0,1), W=(-1,0); methods delta()->tuple[int,int], left()->Direction, right()->Direction. All movement uses direction.delta().
- Geometry: Rect(x:int,y:int,w:int,h:int) validates w>0 and h>0, contains(px,py) checks half-open [x,x+w) and [y,y+h). Obstacle wraps a Rect.
- Arena(width:int,height:int,obstacles:list[Obstacle]) validates positive dimensions and exposes in_bounds(x,y) and is_blocked(x,y) where out-of-bounds and obstacle cells are blocked.
- Actors: Tank(id:str,name:str,x:int,y:int,direction:Direction,health:int=3,speed:int=1) with public attributes including direction; methods barrel_ahead() using direction.delta(), alive(), and clone(). Projectile(pid:int,owner_id:str,x:int,y:int,direction:Direction,speed:int=1) with move() per unit and clone().
- Commands: Command is an instantiable marker with no ABC and no execute method. Subclasses MoveForward(steps:int=1) rejecting steps<1, RotateLeft(), RotateRight(), RotateTo(direction:Direction), Fire() also have no execute method.
- Game(arena:Arena,tanks:dict[str,Tank]) validates unique in-bounds unblocked tank cells, stores deep immutable initial snapshot, and exposes mutable public attributes arena, tanks, projectiles, scores, command_queue, next_projectile_id. Methods: queue_command(player_id:str,command), tick(), reset(), winner(), snapshot().
- Tick order: stable-sort command_queue by player id, apply commands by isinstance dispatch, clear the queue, then process projectiles in ascending pid. MoveForward performs one cell per step, stopping before blocked cells. Fire spawns a projectile at barrel_ahead if free; the same tick's projectile phase moves every projectile (including the new one) by speed one cell at a time, resolving collisions immediately.
- Projectile collision: after each unit step, despawn on out-of-bounds/obstacle or hitting the first non-owner live tank; deal 1 health damage, record exactly one hit and kill (only if health becomes zero), remove the projectile. Scoring uses self.scores.record_hit(projectile.owner_id) and self.scores.record_kill(projectile.owner_id).
- ScoreBoard(player_ids:list[str]) initializes hits and kills maps with zeros for all players; score(player_id)=hits+5*kills. Game construction and reset use ScoreBoard(list(self._initial_tanks)).
- Winner: returns the sole surviving tank id only when at least two tanks were initially supplied and exactly one remains alive; otherwise None.
- Reset: restore deep clones of initial arena and tanks (position, direction, health, speed), clear projectiles and command_queue, recreate zeroed ScoreBoard entries, and set next_projectile_id=0.

## Domain Expectations

- Movement respects Arena bounds and Obstacle blocking; MoveForward stops before entering blocked cells.
- Rotation updates the Tank.direction: left/right by 90 degrees; RotateTo sets an explicit Direction.
- Fire creates a Projectile at barrel_ahead only if that cell is free; otherwise no projectile is spawned.
- Projectile movement and collision resolution are deterministic and happen after commands in the same tick.
- Scoring increments: record_hit adds 1 per hit; record_kill adds 1 per kill; score(player_id)=hits+5*kills.
- Snapshot returns serialized state: arena/tanks/projectiles/scores/winner with Direction serialized as direction.name.
- Winner appears only when one tank remains alive from an initial set of at least two tanks.
- Reset fully restores initial conditions including tanks, arena, scores, projectiles list, command queue, and next_projectile_id=0.

- As a developer, I can construct an Arena and place Tanks with Directions and health to run deterministic simulations.

- As a developer, I can reset the Game to its initial state and confirm scores and IDs are reinitialized.

- Classic grid tank microgames: typically minimal rules, but often lack deterministic snapshots for testing.
- Turn-based board-game simulators: strong determinism and state-serialization patterns.
- Educational Python gridworlds: focus on clarity and testability, sometimes with weaker API discipline.
