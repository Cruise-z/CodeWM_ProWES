## Domain Reasoning

- Core entities are the 21x21 QRMatrix with fixed finder patterns, QRCodec for encode/decode/detect, and QRRenderer for ASCII rendering
- Finder patterns must be placed at exact coordinates with an exact 5x5 pattern definition
- Data bit positions are all non-finder cells in strict row-major order, totaling exactly 366 positions
- Wire format enforces length byte, payload bytes MSB-first, checksum byte (sum mod 256), then zero padding
- Robust validation: decode checks finder correctness, length bounds, data sufficiency, checksum, and all-zero padding
- Detection is defined as successful decode without exceptions
- Rendering produces a deterministic 21-line textual grid with customizable on/off markers and rejects empty markers
- Bounds checking on matrix access must throw for out-of-range indices

## Domain Expectations

- Deterministic 21x21 matrix creation with three exact 5x5 finder markers at (0,0), (0,16), and (16,0)
- QRMatrix::get/set enforce bounds and report errors via std::out_of_range
- Exact count and order of data bit positions: 366 non-finder cells in row-major order
- Encoder rejects text.size() > 40 with std::invalid_argument
- Decoder throws std::runtime_error on invalid finders, bad length, insufficient data, checksum mismatch, or non-zero padding
- detect(matrix) returns true only when decode(matrix) succeeds; otherwise false
- Renderer returns a 21-line string with exactly 20 newline characters and no trailing newline
- Main demonstrates encoding and decoding a fixed literal and prints at most one concise line

## Product Goals

- Deliver a correct, minimal, and deterministic QR-like codec with clear public APIs
- Maintain strict separation of core logic, rendering, app entry, and tests

## User Stories

- As a developer, I can encode a short text into a 21x21 matrix and later decode it back to the original string.
- As a developer, I can detect whether a given matrix encodes a valid payload using detect() without throwing exceptions.
- As a developer, I can render the matrix to a text-based representation with custom on/off markers for console output.
- As a CI engineer, I can build and run tests using CMake and ctest without external dependencies on any platform.

## Competitive Analysis

- ZXing-cpp: Full-featured barcode library with QR detection/decoding; heavier and dependency-rich compared to this minimal fixed-format project
- Nayuki qrcodegen: Portable QR Code generator library; more general-purpose and supports multiple versions/masks/correction levels
- libqrencode: C library for QR Code encoding; broader scope and C interface; not as constrained or minimal as this project

## Requirement Analysis

We must implement a fixed-size QR-like codec with strict contracts: a 21x21 matrix with three precise finder markers, row-major data across exactly 366 non-finder cells, and a simple wire format of length byte, payload bytes MSB-first, checksum, then zero padding. Public APIs are limited to QRMatrix, QRCodec (encode/decode/detect), and QRRenderer (render). Build and test layout is constrained by CMake with a core library and two executables (app and tests). Tests are single-file, header-only includes, deterministic, and cover encode/decode/detect, matrix corruption handling, rendering format, and length rejection. No external dependencies or platform-specific features are allowed. Architecture must use include/src pairing and maintain self-contained headers to avoid circular dependencies.
