## Implementation approach

Preserve protocol files exactly: CMakeLists.txt, src/Main.cpp, tests/test_main.cpp. Use a thin runtime entry that demonstrates the engine deterministically and exits. Separate pure domain logic into cohesive headers under include/ with matching implementations in src/. Build a core library from domain sources, link the demo and tests to it. Tests remain headless-friendly: they include headers only, construct the engine in-memory, and validate moves, alternation, win/draw detection, and reset/history without any I/O, GUI, or network. Keep modules small and domain-specific: Board (grid and cells), Move/MoveHistory (value and auditing), WinDetector (pure rule scanning), and GameEngine (orchestration applying validated moves). Use C++17 only and CMake with add_test. Roles: Alice as Player X, Eve as Player O, and Alex as reviewer via tests.

    GE-->>M: MoveError::None, status InProgress

    GE->>B: validate & set
    GE->>WD: checkWin
    GE-->>M: MoveError::None
    M->>GE: repeat deterministic sequence
    WD-->>GE: winner found (Player X)
    GE-->>M: status WonX
