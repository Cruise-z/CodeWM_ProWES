## Implementation approach

Preserve Maven protocol files exactly and keep runtime entry thin. Use Java 11, default package for all classes, and Maven Surefire configured for JUnit Jupiter. The core is decomposed into concrete domain entities (Player, Move, Board, GameState), a pure rule (WinDetector), and orchestration (Game). Main is a minimal, headless entry that demonstrates a couple of safe moves and returns normally with at most one concise print. Tests are deterministic, offline, and headless; they exercise only the canonical Game API. No GUI, no System.exit, no external dependencies beyond JUnit Jupiter.

Full API specification (explicit repetition):
- The canonical Game API is exactly: Game(int size), Board getBoard(), Player getCurrentPlayer(), GameState getState(), boolean placeMove(int row,int col), boolean undo(), void reset(), java.util.List<Move> getHistory().
- Game(int size) rejects size<5 with IllegalArgumentException and every new or reset game starts with Player.X (X-first/reset rule).
- placeMove has no Player argument: while IN_PROGRESS it returns false without mutation for an out-of-bounds or occupied cell; otherwise it places currentPlayer, appends exactly one Move, evaluates win via WinDetector.hasFiveInRow then draw, and advances to currentPlayer.next() only when the resulting state remains IN_PROGRESS; after a win currentPlayer therefore remains the winner, and every terminal call returns false with no mutation (toggle-only-while-in-progress rule and normal-return/no-System.exit rule).
- GameState uses exactly Status.IN_PROGRESS, Status.DRAW, Status.X_WON, and Status.O_WON; GameState.won(Player.X) produces X_WON and winner X, GameState.won(Player.O) produces O_WON and winner O, while inProgress/draw have an empty winner.
- undo returns false with no mutation when history is empty; otherwise it removes exactly the latest move, clears that board cell, restores currentPlayer to the removed move's player, restores GameState.inProgress(), and returns true (undo semantics).
- reset clears every board cell and the complete history, restores currentPlayer=Player.X and GameState.inProgress(); it must never derive the first player from the pre-reset current turn.
- WinDetector.hasFiveInRow(Board,int,int,Player) counts the just-played stone plus matching stones in both signs of exactly (0,1), (1,0), (1,1), and (1,-1). Five or more contiguous stones wins immediately (four-direction two-sided count).

Logic Analysis (explicit repetition):
- Alternation occurs only while the game remains IN_PROGRESS; after a win, currentPlayer remains the winner (toggle-only-while-in-progress rule).
- Illegal moves (occupied or out-of-bounds) return false with no mutation; terminal state prevents further mutation; normal-return/no-System.exit rule is maintained across runtime and tests.
- Win detection strictly evaluates two-sided contiguous counts for four directions: (0,1), (1,0), (1,1), (1,-1) using the just-placed stone; five or more contiguous stones wins immediately.
- Undo semantics: removes last move, clears its cell, restores currentPlayer to that move's player, and sets state to IN_PROGRESS. Undo returns false with no mutation when history is empty.
- Reset semantics: fully clears board and history; sets currentPlayer to Player.X and state to IN_PROGRESS regardless of prior turn (X-first/reset rule).
- Sequence coverage targets the exact nine moves: (7,3),(0,0),(7,4),(0,2),(7,5),(0,4),(7,6),(0,6),(7,7) with Player.X winning horizontally and remaining the currentPlayer.

Test Scope Plan (explicit repetition):

- Test 1: Main.main returns normally without System.exit; at most one concise print.
- Test 2: The exact single nine-move horizontal win sequence (7,3),(0,0),(7,4),(0,2),(7,5),(0,4),(7,6),(0,6),(7,7) on a single new Game(15); assert all nine placeMove calls are true; final status X_WON, winner Optional.of(Player.X), currentPlayer Player.X, history size 9; then perform exactly one terminal placeMove attempt and assert false with no mutation.
- Test 3: The state fixture: new Game(15) starts X; placeMove(1,1) is true then turn O; repeated placeMove(1,1) and placeMove(-1,0) are false and leave turn O and history size 1; placeMove(2,2) is true and changes turn to X; undo is true, makes (2,2) empty, restores turn O, leaves history size 1 and IN_PROGRESS; reset restores X, empties (1,1), clears history, and IN_PROGRESS.
