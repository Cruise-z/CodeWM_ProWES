## Testing Constraints

- Exactly one protocol-level test file: tests/test_main.cpp
- No third-party frameworks; a single self-contained int main() using only the C++17 standard library
- Deterministic, headless tests; no GUI, no I/O loops, no randomness, no network
- Tests include only headers from include/, never src/*.cpp
- Cover runtime wiring (Runtime::App) and at least one core rule (e.g., deterministic playback advancement)

## Language Convention Requirements

- Use CMake with a clear separation of include/ headers and src/ implementations; every reusable module has matching include/*.h and src/*.cpp
- tests/test_main.cpp must include headers only and must define exactly one int main()
- Prohibit third-party testing libraries; use only C++17 standard library
- Do not rely on transitive includes: each header lists its own required standard headers
- Project-specific 64-bit contract: every header that names a signed 64-bit integer must directly include <cstdint> and spell the type as std::int64_t (never bare int64_t)
- Time/IClock.h must begin with #include <cstdint> and declare virtual std::int64_t now_ms() const noexcept = 0;
- ManualClock and MonotonicClock override exactly std::int64_t now_ms() const noexcept; keep noexcept/const consistent in headers and sources
- src/Main.cpp contains only a minimal int main() that returns Runtime::App().run_demo() and has no interactive or long-running loop
- CMake directly builds tests with add_executable(video_player_tests tests/test_main.cpp), links the core library, calls enable_testing(), and registers add_test without find_package or network

## Domain Reasoning

- Playback timing is a pure-domain responsibility driven by a clock boundary; implement IClock with ManualClock (deterministic) and MonotonicClock (real-time) to separate environment from logic
- Player manages state transitions: Stopped, Paused, Playing; updates position using clock deltas, clamping to media duration
- Playlist provides deterministic navigation and selection among MediaMetadata entries; navigation returns success/failure without side effects beyond selection
- MediaMetadata contains validated duration and descriptive fields; duration bounds checks are critical for seek and playback clamping
- Volume and mute are domain properties: volume as an integer 0–100, independent mute flag; effective output can be inferred but no audio output
- Seeking must clamp within [0, duration] and update last-timestamp references coherently
- Runtime/App composes the clock, playlist, and player for a small deterministic demo without I/O loops or GUI
- Tests must drive ManualClock to assert deterministic playback progress and rule enforcement

## Domain Expectations

- MediaMetadata validates non-negative durations; zero-duration media is allowed but cannot advance playback
- Player play() sets state to Playing only when a current media exists; pause() sets Paused; stop() sets Stopped and resets position to 0
- Player seek(ms) clamps to [0, current_media_duration] and preserves state (Playing/Paused) while resetting last-tick reference
- Player update_to_now() uses IClock to compute elapsed time since last tick when in Playing; advances position and clamps to duration; on reaching duration, sets state to Paused and position to duration
- Player supports set_volume(int 0..100) and mute/unmute; volume clamped to bounds; mute is independent from volume level
- Playlist supports add(), size(), get(index), select(index) returning bool, current_index(), next()/prev() with bounds; no wrap-around by default
- Switching playlist item resets player position to 0 and sets state to Stopped; subsequent play() begins from 0
- MonotonicClock reads steady time; ManualClock provides deterministic control for tests and demos

## Product Goals

- Deliver a clean, deterministic C++17 core for a headless video player domain (no decoding) with clear separation of concerns
- Provide a minimal, strictly specified build and test pipeline that is self-contained and reproducible

## User Stories

- As a user, I can load a playlist of media items and move to next/previous items deterministically
- As a user, I can play, pause, and stop playback and see position bounded by each media’s duration
- As a user, I can seek to a specific position within media and the player clamps to valid bounds
- As a user, I can set volume and toggle mute independently of volume level
- As a developer, I can run a deterministic demo and tests without external dependencies or manual steps

## Requirement Analysis

We must produce a C++17 repository with strict protocol: CMakeLists.txt as the sole build file, src/Main.cpp as the minimal runtime entry returning Runtime::App().run_demo(), and tests/test_main.cpp as the only test file with a single int main(). The architecture must use include/*.h and src/*.cpp pairs for reusable modules. Deterministic time must be provided via an IClock boundary with a ManualClock for tests and a MonotonicClock for runtime. The 64-bit timing contract is strict: every header that names a signed 64-bit integer directly includes <cstdint> and uses std::int64_t spelling; IClock.h must begin with <cstdint> and declare virtual std::int64_t now_ms() const noexcept = 0; ManualClock and MonotonicClock must override exactly that signature consistently in headers and sources. Domain behavior includes media metadata (duration), playlist navigation without wrap, playback state transitions (play/pause/stop), seek and duration clamping, volume and mute handling, and a headless deterministic update path. Tests need to be concise (2–4 tests, under ~150 LOC), deterministic, and headless. The CMake test target must be built directly (no find_package), registered with add_test, and invoked via ctest. Public API must be canonical so tests import only headers. Files should be small (ideally under 150 LOC each) and ordered by dependency to avoid circular includes.

## UI / UX / Interaction Design draft

Headless runtime with a tiny demo: construct a playlist, create a Player with ManualClock, perform a simple sequence (play, advance time, pause/stop), and exit. No GUI rendering or input loops. Tests avoid real rendering and manual input by using ManualClock and direct API calls.

## Anything UNCLEAR

Actual media decoding, audio/video output, and file I/O are out of scope; we focus on domain logic only. Playlist wrap-around is unspecified; we choose no wrap by default. End-of-media behavior is chosen as auto-pause at duration with position clamped; if alternative behavior (auto-stop or auto-next) is desired, it can be specified later.
