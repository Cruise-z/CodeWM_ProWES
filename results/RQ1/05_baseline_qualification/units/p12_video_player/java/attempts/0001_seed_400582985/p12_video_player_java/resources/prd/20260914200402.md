## Domain Reasoning

- Playback progression must be driven by a deterministic in-memory clock (DeterministicClock) only; time is advanced explicitly via advance(deltaMillis) and observed via onClockAdvanced()
- PlaybackController governs PlayerState transitions among STOPPED, PLAYING, and PAUSED, clamping position within [0, duration] and switching to STOPPED exactly at end-of-media
- Playlist provides safe navigation (next/previous with clamped indices) and supports empty-playlist edge cases
- PlayerState zero-arg constructor MUST initialize currentIndex=0, positionMillis=0, status=STOPPED; initializing currentIndex to -1 is forbidden
- VolumeControl tracks volume [0,100], mute flag, and lastNonMuted with the rule: setVolume always updates both volume and lastNonMuted even while muted; unmute restores lastNonMuted
- PlayerSnapshot aggregates a read-only projection combining playlist metadata, player state, and volume, providing safe defaults for empty/invalid index
- Seek operations clamp to the current item's duration; next/previous change index using Playlist helpers and reset position only when index actually changes

## Domain Expectations

- MediaItem validates nonblank id/title and positive durationMillis; exposes getters for id, title, durationMillis
- Playlist stores MediaItem instances (ArrayList), rejects null adds, and provides size/getAt/removeAt with standard semantics; hasNext/hasPrevious and nextIndex/previousIndex are bounds-safe, returning -1 for empty lists
- PlayerState zero-arg constructor sets currentIndex=0, positionMillis=0, status=STOPPED; setters validate non-negative position and non-null status; resetPosition sets position to 0
- VolumeControl starts with volume=100, lastNonMuted=100, muted=false; setVolume assigns both volume and lastNonMuted even when muted; mute flips muted=true without changing volumes; unmute restores volume=lastNonMuted; getEffectiveVolume returns 0 when muted else volume
- DeterministicClock starts at 0, rejects negative advances, and adds nonnegative deltas only
- PlaybackController.play rejects an empty playlist; for nonempty playlists, accept index 0, reset position to zero only if already at duration, and set status=PLAYING
- onClockAdvanced uses nonnegative delta since lastTick, advances only when status=PLAYING, clamps at duration, and switches status to STOPPED while keeping position exactly at duration
- PlayerSnapshot.from returns an immutable snapshot: for invalid/empty index use empty title and duration 0; for valid index return the real media metadata with current position, status, and volume/mute state

## Product Goals

## User Stories

- As a user, I can play, pause, and stop a media item from a playlist and see accurate position tracking.
- As a user, I can seek within the current media item with clamping at the media duration.
- As a user, I can navigate to next or previous items, staying at bounds when already at the last or first item.
- As a user, I can adjust volume, mute/unmute, and expect unmute to restore the most recently set volume even if set while muted.
- As a user, I can retrieve a snapshot of the current playback state and metadata at any time.

## Competitive Analysis

- VLC media player: broad format support and robust controls; much larger scope than required
- Windows Media Player: integrated experience; not deterministic or headless-friendly for tests
- QuickTime Player: simple UI; not suitable for deterministic core testing
- ExoPlayer (Android library): modular and testable; includes network/decoder concerns beyond scope
- ffplay (FFmpeg): powerful but tied to native, non-Java ecosystems and real-time I/O

## Requirement Analysis

We must build a Java 11 Maven project with exactly these default-package files and no packages: pom.xml; src/main/java/MediaItem.java; src/main/java/Playlist.java; src/main/java/PlayerState.java; src/main/java/VolumeControl.java; src/main/java/DeterministicClock.java; src/main/java/PlayerSnapshot.java; src/main/java/PlaybackController.java; src/main/java/Main.java; src/test/java/MainTest.java. Main.java must be the runtime entry in the default package and only perform a small, bounded, non-interactive demo. The pom.xml must compile with source/target 11 and declare org.junit.jupiter:junit-jupiter (test scope) and a Maven Surefire version that runs JUnit 5. The design must strictly follow the deterministic video-player state contract: PlayerState zero-arg constructor initializes currentIndex=0 (forbidden to use -1), positionMillis=0, and status=STOPPED; VolumeControl.setVolume always assigns both volume and lastNonMuted even while muted; DeterministicClock is a pure counter with no wall clock. PlaybackController orchestrates play/pause/stop/seek/next/previous per the clamping and state-transition rules, and onClockAdvanced handles time progression and end-of-media STOPPED transition. PlayerSnapshot is immutable and returns safe defaults on empty/invalid index. Tests must be a single file with exactly three JUnit Jupiter tests using literal fixtures: (1) single item duration 5000ms: after play and 5000ms advance, snapshot shows STOPPED with position=5000; (2) two items with durations 3000/4000: seek to 5000 clamps to 3000; next/previous semantics respect bounds and reset position only on index change; (3) volume 70 -> mute -> set 30 while muted -> unmute results in volume 30 and effective 30.
