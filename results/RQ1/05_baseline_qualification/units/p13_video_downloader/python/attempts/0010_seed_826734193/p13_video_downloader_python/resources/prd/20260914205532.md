## Domain Reasoning

- The domain centers on offline, deterministic download simulations with strict validation and safe naming
- URL validation gates all requests: accept only http/https with nonempty netloc and path; reject whitespace
- DownloadRequest captures url, format (mp4/webm/mkv), and optional sanitized output hint; maps formats to extensions
- Progress tracks transferred bytes vs optional total and notifies listeners synchronously
- CancellationToken provides cooperative cancellation checked before each chunk
- TransferAdapter abstracts transfer behavior; FakeTransferAdapter simulates deterministic chunked transfer and naming uniqueness
- DownloadQueue manages job lifecycle (pending, running, completed, failed, cancelled) with synchronous processing and pre-start cancellation
- Main.py offers a thin demo wiring the queue and adapter, returning a status dict as the public runtime output

## Domain Expectations

- URL validation enforces http/https schemes, nonempty netloc and path, no embedded whitespace, and trims surrounding whitespace; invalid inputs raise InvalidURLError
- Supported formats are case-insensitive mp4, webm, mkv; invalid formats raise InvalidFormatError; extension() returns ".mp4", ".webm", or ".mkv"
- sanitize_filename: strips, collapses whitespace to underscores, removes path separators and non [A-Za-z0-9._-], trims edge dots/underscores, fallback "download"
- unique_name(base, existing): returns base if free else adds " (n)" before the extension; fixture unique_name("clip.mp4", {"clip.mp4"}) -> "clip (1).mp4"
- Progress.update(delta) rejects negative, clamps at total if set, and synchronously notifies listeners with (transferred, total); percent() returns Optional[float]
- FakeTransferAdapter.total_bytes(req) returns mapping total or raises TransferError if absent
- FakeTransferAdapter.transfer(req, progress, cancel) checks cancellation before each chunk, raises CancelledError on cancellation, updates progress, and returns TransferResult with deterministic unique final_name
- DownloadQueue supports enqueue -> id, pre-start cancel(job_id) that sets 0 progress and state cancelled for pending jobs, process_next/process_all synchronous execution, and get_status(job_id) -> dict with state, transferred, total, final_name

## Product Goals

- Provide a clear, deterministic core downloader architecture that is easy to test and extend
- Guarantee strict input validation and safe output naming to prevent misuse and collisions
- Deliver a minimal runtime entry demonstrating end-to-end flow without side effects

## User Stories

- As a user, I want to queue multiple downloads and process them sequentially so I can manage tasks deterministically.
- As a user, I want to cancel a pending download before it starts to avoid unnecessary work.
- As a user, I want progress updates and a final status with total bytes and completion state.
- As a user, I want filenames to be sanitized and made unique so saved outputs do not collide.
- As a user, I want invalid URLs or formats to be rejected with explicit errors.

## Competitive Analysis

- yt-dlp: powerful downloader with wide protocol support; not deterministic nor offline for tests

- aria2: advanced downloader with multi-source features; not suitable for offline deterministic tests
- Requests-based examples: common Python HTTP download snippets; rely on network and I/O
- Educational mock downloader samples: demonstrate abstractions, but often lack strict validation and tests
