## Implementation approach

Preserve Maven protocol files exactly and target Java 11 without preview features. Keep Main.java thin and non-interactive. Model the domain around a canonical VideoDownloader API that orchestrates a queue of DownloadTask. Separate pure domain (validation, request construction, task state machine, queue orchestration) from the transfer boundary via TransferAdapter/TransferSession interfaces. Provide a deterministic OfflineDeterministicAdapter that simulates chunked transfers offline and headlessly for tests. Use enums and small interfaces to keep the architecture simple and composable. Tests use only the canonical API, run offline, and assert deterministic progress/cancellation and validation/naming behavior.

## Program call flow

sequenceDiagram
    participant M as Main
    participant A as OfflineDeterministicAdapter
    participant VD as VideoDownloader
    participant DT as DownloadTask
    M->>A: new OfflineDeterministicAdapter()
    M->>VD: new VideoDownloader(A)
    M->>VD: requestDownload(url1, MP4, name1)
    M->>VD: requestDownload(url2, WEBM, name2)
    M->>VD: startPending()
    loop few ticks
        M->>VD: tick()
        VD->>DT: tick() for each RUNNING
        DT->>DT: session.step(), update progress/status
    end
    M->>VD: getStatus(taskId), getProgress(taskId), getOutputName(taskId)
    VD-->>M: statuses and progress
    Note over DT,A: ProgressListener callbacks occur on each step
    DT-->>VD: status becomes COMPLETED/CANCELLED/FAILED as appropriate
