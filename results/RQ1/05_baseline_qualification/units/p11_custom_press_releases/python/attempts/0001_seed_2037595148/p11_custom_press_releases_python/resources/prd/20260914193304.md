## Original Requirements

Generate a complete medium-size Python 3.10 repository architecture for: Custom press releases. Follow a strict 10-file layout: requirements.txt; press_releases/errors.py; press_releases/types.py; press_releases/template.py; press_releases/validation.py; press_releases/press_release.py; press_releases/search.py; press_releases/__init__.py; Main.py; tests/test_main.py. Keep Main.py thin; reusable modules live in a snake_case package. Use pytest only; test command is python -m pytest -q. No datetime/time/random/uuid/pathlib/os/threading or clock abstractions. Domain lifecycle: State enum DRAFT->REVIEW->PUBLISHED; Template with literal sorted replacement loop; validation returns booleans; PressRelease is a mutable class (not a dataclass), non-validating constructor, deterministic integer version history, tags with unique insertion order, plain-text rendering via Template. Search by tag and text with specified behaviors. __init__.py re-exports canonical symbols only. Tests: exactly one test file with three cases, including run_demo import from Main and specific lifecycle, rendering, validation, and error expectations.

## Domain Reasoning

- Entity: PressRelease with mutable state and fields (id, headline, body, contact, template, custom_fields, tags, version history)
- Value Objects: Contact, VersionEntry as frozen dataclasses with generated initializers
- State Machine: transitions DRAFT -> REVIEW -> PUBLISHED with strict guards
- Validation: headline/body strings and contact structure, returning booleans
- Template Rendering: literal placeholder replacement with sorted keys; leaves unknown placeholders
- Versioning: integer-only version entries appended on first publish
- Tags and Search: insertion-ordered unique tags; search by tag and case-insensitive text
- Boundaries: no clocks, randomness, filesystem, or OS dependencies; deterministic behavior

## Domain Expectations

- PressRelease constructor does not validate; invalid candidates can be created
- validate() returns False for invalid headline/body/contact; never throws
- submit_for_review() requires valid content and DRAFT state; else raises DomainError/InvalidTransitionError
- publish() requires REVIEW state; on first publish, append exactly VersionEntry(number=1, rendered_text)
- Template.render replaces placeholders using a sorted key loop, leaving missing placeholders intact
- tags are trimmed, non-blank, unique, and preserve insertion order; add_tag raises DomainError for blank
- search_by_tag returns releases with exact normalized tag matches; ignores None entries; preserves order
- search_text returns releases where query is in headline or body (case-insensitive); preserves order

## Requirement Analysis

We must implement a Python 3.10 domain package for custom press releases with a strict 10-file layout and a single pytest suite. Main.py remains a thin entrypoint exposing run_demo. Core modules define errors, types, template rendering with a literal sorted-field replacement loop, validation, a mutable PressRelease with state transitions, and search utilities. No datetime/time/random/uuid/pathlib/os/threading or clock abstractions are permitted. The constructor for PressRelease is non-validating; validations return booleans; invalid transitions raise domain-specific exceptions. Version history uses monotonically increasing integer numbers and captures rendered text on first publish. __init__.py re-exports only canonical names. Tests must be concise (3 cases), deterministic, import run_demo from Main, and confirm lifecycle, rendering, validation, and search behaviors. Maintain an acyclic import graph: errors -> types -> template -> validation -> press_release -> search -> __init__ -> Main -> tests.
