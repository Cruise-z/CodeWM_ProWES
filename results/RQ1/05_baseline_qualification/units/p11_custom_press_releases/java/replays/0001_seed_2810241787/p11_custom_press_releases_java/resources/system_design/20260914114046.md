## Implementation approach

Bob (Architect) proposes a simple, deterministic Java 11 Maven project with exactly 10 files, in strict dependency order, implementing the Custom press releases domain. We preserve the protocol: build file pom.xml, runtime entry src/main/java/Main.java, and single test target src/test/java/MainTest.java executed by mvn -q test. We keep every class in the default package (no package declarations) to avoid import mismatches. We use only headless, offline, pure Java 11 logic: no GUI, no filesystem, no network, no clock, no randomness.

Core domain model:
- ReleaseState: sole enum owner of DRAFT, REVIEW, PUBLISHED.
- Version: sole value object owner; number and renderedText with value-based equality, hashCode, getters, toString.
- Template: immutable name+content with deterministic placeholder substitution: literal {{key}} replaced if key is provided in the given Map; missing placeholders remain; null map treated as empty.
- Validator: stateless static methods for headline/body/contact validation. Headline/body require non-null/non-blank. Contact requires exactly one '@' and non-empty local and domain parts.
- PressRelease: aggregate root owning id, headline, body, contact, template, customFields, tags, state, and version history. Starts DRAFT. submitForReview() requires validate()==true and state DRAFT; otherwise IllegalStateException. publish() requires REVIEW; on first publication append exactly one Version(1, renderPlainText()) and move to PUBLISHED. Exposes defensive copies in insertion order for tags and versions. renderPlainText() constructs a new field map of headline, body, contact plus constructor customFields, then delegates to Template.applyCustomFields.
- TaggingSystem: stateless searchByTag(List<PressRelease>, String) that returns releases whose tags contain the exact trimmed tag, preserving input order. Nulls are treated defensively: null list or null tag yields empty result.
- RenderService: stateless toPlainText(PressRelease) delegating to release.renderPlainText; no ownership of ReleaseState or Version.

Maven/JUnit setup: pom.xml declares Java 11 compilation, the org.junit.jupiter:junit-jupiter dependency with test scope (as mandated) plus api/engine artifacts for runtime, and Maven Surefire 3.x to run JUnit 5. Tests are concise and deterministic.

Concrete implementation tasks by file (dependency-first order):
1) pom.xml: Set groupId/artifactId/version; configure maven-compiler-plugin for Java 11; add org.junit.jupiter:junit-jupiter with test scope; add junit-jupiter-api and junit-jupiter-engine; configure surefire 3.1.2 to enable JUnit 5.
2) src/main/java/ReleaseState.java: Define exactly public enum ReleaseState { DRAFT, REVIEW, PUBLISHED } as the sole owner.
3) src/main/java/Version.java: Define public final class Version with private final int number; private final String renderedText; public constructor Version(int,String); getters getNumber/getRenderedText; implement equals/hashCode/toString value-based.
4) src/main/java/Template.java: Define public final class Template(name,content) immutable; getters; applyCustomFields(Map<String,String>): if fields is null treat as empty; replace literal {{key}} with provided value (null values treated as empty string), others unchanged; no side effects.
5) src/main/java/Validator.java: Define public final class Validator with exactly static boolean validateHeadline(String), validateBody(String), validateContact(String). Headline/body: non-null and not blank. Contact: non-null, contains exactly one '@', with non-empty trimmed local and domain parts.
6) src/main/java/PressRelease.java: Define public final class PressRelease with constructor PressRelease(String id,String headline,String body,String contact,Template template,Map<String,String> customFields). Internal state: ReleaseState, insertion-ordered LinkedHashSet<String> tags, insertion-ordered List<Version> versionHistory, LinkedHashMap<String,String> customFields copy. Expose getters getId/getHeadline/getBody/getContact/getState; boolean validate(); void submitForReview(); void publish(); void addTag(String) (ignore null/blank; store trimmed; preserve insertion order; avoid duplicates); List<String> getTags() returns defensive copy in insertion order; String renderPlainText(); List<Version> getVersionHistory() returns defensive copy in order. Enforce invalid state transitions with IllegalStateException. On first publish (from REVIEW), append exactly new Version(1, renderPlainText()) and move to PUBLISHED.
7) src/main/java/TaggingSystem.java: Stateless utility with static List<PressRelease> searchByTag(List<PressRelease>, String) that returns a new list preserving input order and matching exact trimmed tag against each release.getTags(). Contains no state.
8) src/main/java/RenderService.java: Stateless utility with static String toPlainText(PressRelease) delegating to release.renderPlainText().
9) src/main/java/Main.java: Thin non-interactive demo that constructs a Template and a PressRelease, exercises validate/submitForReview/publish/render, prints one or two lines, and exits normally.
10) src/test/java/MainTest.java: Exactly three JUnit 5 tests: (1) Main.main(new String[0]) returns normally; (2) Template("basic","{{headline}}|{{body}}|{{contact}}") with fields for headline/body/contact yields Hello|Body|a@b.com; Validator accepts those and rejects blank headline and contact "invalid"; (3) Lifecycle test for release id "r1": assert initial DRAFT; submitForReview then REVIEW; add tag "media"; publish then PUBLISHED; render exact Hello|Body|a@b.com; assert version history size==1 with Version number==1 and same text; assert TaggingSystem.searchByTag(Arrays.asList(release),"media") returns only that release.

This architecture keeps environment-dependent code minimal (Main only), ensures deterministic behavior, and separates pure domain logic for reliable automated testing.

## Program call flow

sequenceDiagram
    participant M as Main
    participant T as Template
    participant PR as PressRelease
    participant RS as RenderService
    M->>T: new Template("basic", "{{headline}}|{{body}}|{{contact}}")
    M->>PR: new PressRelease(id, headline, body, contact, T, customFields)
    M->>PR: validate()
    alt valid
      M->>PR: submitForReview()
      M->>PR: publish()
      M->>RS: toPlainText(PR)
      RS->>PR: renderPlainText()
      PR-->>RS: rendered text
      RS-->>M: rendered text
    else invalid
      M->>M: handle exception or skip publish
    end
