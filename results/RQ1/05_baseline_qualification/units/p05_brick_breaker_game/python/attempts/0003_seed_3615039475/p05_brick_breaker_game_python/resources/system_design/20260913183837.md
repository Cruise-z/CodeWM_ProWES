## Implementation approach

Preserve protocol files exactly: requirements.txt, Main.py, tests/test_main.py. Keep Main.py thin and headless, running a single deterministic demo step and exiting. Place reusable logic in a snake_case package brick_breaker with an acyclic import graph. Ownership: config.py owns GameConfig and imports no project modules. level.py and game.py literally import GameConfig via 'from .config import GameConfig'. level.py must not import game.py. game.py may import make_grid_level from level.py. Separate domain entities (ball, paddle, brick) from pure rules (collision) and orchestration (game). No GUI or external frameworks; tests exercise pure logic deterministically with discrete ticks and abstracted input (left/right/none). Only pytest is listed in requirements.txt. Target Python 3.10 and avoid 3.11+ APIs. The single protocol test verifies runtime wiring via Main.run_demo and covers representative rules: a brick hit increments score and brick removal; a bottom-out decrements lives and resets level.

## Program call flow

sequenceDiagram
    participant M as Main
    participant G as Game
    participant C as Collision
    participant L as Level
    M->>G: construct(GameConfig())
    G->>L: make_grid_level(config)
    M->>G: tick(input_action='none')
    G->>G: move paddle per input
    G->>G: ball.step()
    G->>C: reflect_off_walls(ball, width, height)
    G->>C: collide_ball_with_paddle(ball, paddle)
    G->>L: iterate bricks
    G->>C: collide_ball_with_rect(ball, brick.x, brick.y, brick.w, brick.h)
    C-->>G: axis of reflection or none
    G->>G: update score/lives/status
    G-->>M: return snapshot dict
