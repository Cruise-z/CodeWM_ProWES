## Implementation approach

Preserve protocol files exactly: CMakeLists.txt, src/Main.cpp, tests/test_main.cpp. Build a core static library from src/*.cpp (excluding Main.cpp), link it into a thin runtime executable and a single test executable registered with ctest. Split domain into concrete, reusable modules under include/*.h and src/*.cpp pairs: Vector2, Ball, Paddle, Brick, Level, Collision, Playfield, GameEngine. Keep headers self-contained and only use the C++17 standard library. Core logic is deterministic, headless, and time-stepped; no rendering, input devices, threads, clocks, or network. The runtime entry demonstrates a few steps and prints a concise summary. The single test drives the core via headers only.
Full API specification: All public types live in namespace breakout. Public API includes Level::remaining() and GameEngine::remainingBricks() returning std::size_t; ensure include/Level.h and include/GameEngine.h each directly contain #include <cstddef>. GameEngine uses breakout::Collision (declared in include/Collision.h). src/GameEngine.cpp directly contains #include "Collision.h" and #include <cmath>, and spells square root as std::sqrt. Tokens repeated here as required: #include <cstddef>, std::size_t, #include "Collision.h", #include <cmath>, std::sqrt.
Logic Analysis: Deterministic step(dt, input) updates ball motion, resolves collisions using axis-aligned boxes (paddle/bricks) vs circle (ball), updates score/lives, and level progression. Prevent tunneling via simple pre/post checks and reflective responses. Tokens repeated here as required: #include <cstddef>, std::size_t, #include "Collision.h", #include <cmath>, std::sqrt.
Shared Knowledge: Keep physics simple and reproducible; input commands are symbolic (e.g., move left/right/none) and clamped to playfield. Level grids are fixed-size vectors of bricks; durability decrements on hit; removal when zero increases score. Enforce the compilation contract across the codebase for Level::remaining and GameEngine::remainingBricks with std::size_t, and ensure src/GameEngine.cpp includes #include "Collision.h" and #include <cmath> and uses std::sqrt. Tokens repeated: #include <cstddef>, std::size_t, #include "Collision.h", #include <cmath>, std::sqrt.
Level/GameEngine tasks: Level manages brick layout, counts remaining via Level::remaining() -> std::size_t (with #include <cstddef> in include/Level.h, and definition in src/Level.cpp returning std::size_t). GameEngine orchestrates: exposes GameEngine::remainingBricks() -> std::size_t (with #include <cstddef> in include/GameEngine.h; definition in src/GameEngine.cpp returns std::size_t). src/GameEngine.cpp must directly contain #include "Collision.h" and #include <cmath>, and compute any square roots via std::sqrt to comply.

## Program call flow

sequenceDiagram
    participant M as Main (src/Main.cpp)
    participant GE as breakout::GameEngine
    participant LV as breakout::Level
    participant PF as breakout::Playfield
    participant CL as breakout::Collision
    M->>PF: construct(width,height)
    M->>LV: generateGrid(rows, cols, origin, cellSize, hp)
    M->>GE: construct(PF, LV, Ball, Paddle)
    loop fixed ticks
        M->>GE: step(dt, Input)
        GE->>GE: integrate ball, clamp paddle
        GE->>CL: circleVsAABB(ball, walls/paddle/brick)
        CL-->>GE: collision result
        GE->>GE: reflect velocity, update score/lives, remove brick
    end
    GE-->>M: report score, lives, remainingBricks()
    Note right of GE: Contract reminders inside impl: #include "Collision.h", #include <cmath>, std::sqrt
