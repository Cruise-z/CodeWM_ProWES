## Testing Constraints

- Exactly one protocol-level test file: tests/test_main.cpp
- Automated, deterministic, headless; no GUI, network, filesystem, clock, or randomness
- tests/test_main.cpp includes headers only (never .cpp), defines exactly one int main()
- Contains exactly three independently scoped blocks: (1) basic create/list/summary, (2) invalid title/date rejection (with its own local existing_id), (3) normalized-tag and due-date/priority ordering
- Do not reference a local id across blocks; each block owns its variables
- Avoid braced-initializer directly inside assert; use a named expected vector or double-parenthesized assert
- Use the canonical public API only; no test-only backdoors; keep under ~150 LOC
- Run tests with: ctest --test-dir build --output-on-failure

## Domain Reasoning

- Core entities: Task (id, title, description, due_date, priority, tags, completed) and Priority enum
- Date validation and comparison rules (YYYY-MM-DD; strict digit and range checks; empty date allowed and sorts after valid dates)
- Query: filter by completion, minimum priority, due_before/due_after, and require_tags; sorting by either due-then-priority or by title; deterministic tie-breaking
- In-memory persistence boundary via ITaskStore and InMemoryTaskStore; stable storage order not exposed (defensive copies returned)
- TaskManager orchestrates ID assignment (monotonic starting at 1), validation, normalization, and list/summarize operations
- Deterministic normalization of tags: trim, lowercase/normalize, remove empties, sort, deduplicate
- Validation of inputs: non-empty, valid title; due date either empty or valid; edit re-validates; operations on missing ids fail gracefully
- Deterministic summary: pair<completed_count, pending_count> from current store snapshot

## Domain Expectations

- Create task assigns next ID starting at 1, sets completed=false, normalizes tags, validates title and optional due date
- Edit task re-validates title/due_date and updates fields; throws std::invalid_argument for bad data
- Delete task returns false if id not found; set_completed returns false on missing id
- List returns filtered copy sorted deterministically per SortOrder; empty due dates sort after valid ones; higher priority sorted earlier within same due date
- Filter requires all requested normalized tags (set inclusion), supports due_before and due_after ranges
- Tag normalization removes empties, trims whitespace, applies NormalizeTag, sorts and deduplicates deterministically
- Store get_all returns ascending-id defensive vector; find returns pointer into map for update convenience
- Summarize returns pair<completed_count, pending_count> reflecting current store state

## User Stories

- As a user, I can create tasks with title, optional description, optional due date, priority, and tags
- As a user, I can edit and delete tasks; invalid titles or dates are rejected
- As a user, I can mark tasks as completed and see summary counts of completed vs pending
- As a user, I can filter tasks by status, minimum priority, due date ranges, and required tags
- As a user, I can view tasks sorted by due date then priority (or by title) in a deterministic order
