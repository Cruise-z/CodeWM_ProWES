## Domain Reasoning

- Tasks have identity, title, optional description, priority, optional due date, normalized tags, and completion state.
- Priority must be an enum with LOW, MEDIUM, HIGH and a deterministic order_value 0/1/2; mapping from strings allows low/med/medium/high and raises only ValidationError for all other values.
- Task title validation: strip whitespace and require non-blank; ValidationError on invalid titles.
- Tag normalization: strip, lowercase, remove empties, deduplicate, and sort deterministically.
- Completion transitions: complete is idempotent and preserves first completion timestamp; uncomplete clears it.
- Filtering and sorting are pure functions: no mutation of input collections or tasks.
- Repository boundary: in-memory persistence with sequential IDs starting from 1; list_all returns deterministic id-sorted results; duplicate detection yields ValidationError; missing-id yields NotFoundError.
- Clock boundary: abstract clock with FixedClock for deterministic dates and SystemClock for runtime; tests use only FixedClock.
- Service layer: validates inputs, creates/edits/deletes tasks, toggles completion, lists tasks, and returns a deterministic summary with specific keys and uppercase priority buckets.

## Domain Expectations

- Priority.from_value accepts a Priority or supported strings (low, med, medium, high) and raises only ValidationError on invalid values.
- Task dataclass enforces normalized title and tags; due_date can be None.
- mark_complete_on(date) is idempotent and never overwrites an existing completed_at.
- mark_incomplete() clears completed state including completed_at.
- filter_tasks(criteria) supports tag matching with ANY/ALL modes without mutating inputs.
- sort_tasks(keys, direction) is stable and uses id ascending as final tie-break; for due dates, real dates sort before None in ascending order.
- Repository generates sequential IDs from 1 and returns lists sorted by id.
- Service summary returns total, completed, pending, by_priority (keys: LOW/MEDIUM/HIGH), and completed_today based on Clock.today.

## User Stories

- As a user, I can create a task with a title, priority, optional due date, and tags.
- As a user, I can mark a task as completed and see when it was completed.
- As a user, I can edit or delete existing tasks by id.
- As a user, I can list tasks, filter by tags, and sort by due date, priority, title, or completion.
- As a user, I can view a summary of totals, completion counts, and counts by priority.

## Competitive Analysis

- Todoist: Full-featured task management with priorities, tags, filters, and reports.

- Notion Tasks: Flexible but less deterministic behavior for programmatic testing.
