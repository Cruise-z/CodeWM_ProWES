## Domain Reasoning

- Entity lifecycle integrity: create, read, update, delete with stable identifiers
- Validation boundaries: deterministic validation rules and precise error signaling
- Name uniqueness: enforce duplicate-name prevention at repository boundary
- Search semantics: filter/sort plus pagination with clear offset/limit contracts
- Time and audit separation: clock as boundary, audit trail records explicit timestamps
- Determinism: FixedClock ensures repeatable timestamps; Service is sole clock consumer
- In-memory repository abstraction: isolated, testable storage without I/O
- Public API coherence: canonical exports for Item, Page, paginate, Repository, Service, etc.

## Domain Expectations

- Items have stable IDs, names, and timestamps reflecting changes
- Create rejects invalid input and duplicate names; raises ValidationError or DuplicateNameError
- Read by ID returns Item or raises NotFoundError
- Update modifies attributes, preserves ID, enforces name uniqueness, and timestamps the change
- Delete removes an Item by ID and records an audit event; missing ID raises NotFoundError
- Search returns sorted, filtered lists with paginate enforcing non-negative offset/limit
- AuditTrail records operation type, item id/name, and exact timestamp provided by Service
- Service calls clock.now() exactly once per mutating operation and reuses it for audit and entity

## Product Goals

- Deliver a correct, deterministic CRUD core with audit and pagination
- Keep architecture clear, acyclic, and easy to maintain
- Provide a concise, reliable automated test path with minimal dependencies

## User Stories

- As an operator, I can create an item with a unique name; its creation is timestamped and audited.
- As an operator, I can read an item by its ID and see its latest state and timestamps.
- As an operator, I can update an item’s name and see the change reflected with a new timestamp and audit.
- As an operator, I can delete an item and have the deletion recorded in the audit trail.
- As an operator, I can list and paginate items deterministically using limit and offset.
