## Domain Reasoning

- Core entities: Priority and Task with validation and normalized tags
- Repository boundary: TaskRepository interface and in-memory implementation
- Filtering and sorting utilities that operate on lists without mutation
- Service layer (TodoService) orchestrating CRUD, completion, listing, and summaries
- Deterministic demo wiring in Main returning a specific summary map
- Strict rules about IDs, validation order, and increment behavior

## Domain Expectations

- Tasks have id>0, non-blank title, optional due date, normalized tags; priority required
- Repository enforces unique IDs on add, presence on save, and safe deletion semantics
- Filtering supports nullable constraints for completed, priority, and required tags
- Sorting orders by priority rank (desc), due date (non-null first, asc), case-insensitive title, then id
- Service createTask increments nextId only after successful save
- Service edit/setCompleted must throw IllegalArgumentException for missing ids
- Summary returns map with keys total, completed, pending, overdue; overdue incomplete tasks with dueDate strictly before today

## Product Goals

- Deliver a correct, compile-safe Java 11 implementation that meets the strict API and import audits
- Keep core logic pure, deterministic, and decoupled from runtime concerns
- Provide concise yet comprehensive tests that validate key behavior paths

## User Stories

- As a user, I can create a task with title, description, priority, due date, and tags, and the system assigns a unique id starting at 1.
- As a user, I can edit a task’s fields and mark it as completed or not.
- As a user, I can delete a task by id and see whether deletion occurred.
- As a user, I can list tasks filtered by completion, priority, and required tags, sorted deterministically.
- As a user, I can get a summary of total, completed, pending, and overdue tasks for a specific date.

## Requirement Analysis

We must implement exactly 10 files in a strict dependency order with Java 11 and Maven. All classes live in the default package and must include exact literal import lists specified by the contract. The domain API is fixed: Priority enum with rank; Task class with validation, normalized tags, getters, edit, setCompleted; TaskRepository interface; InMemoryTaskRepository with LinkedHashMap storage and specified behaviors; TaskFilter and TaskSorter pure utilities with explicit normalization and comparator rules; TodoService with precise API, create order, and summary semantics; Main with runDemo returning a known map and main invoking it; and one JUnit Jupiter test file with four tests. We must avoid banned features (streams, Optional, etc.), ensure explicit imports for all referenced JDK types, and adhere to the default package rule to avoid package/import mismatches. Tests must be deterministic and run via mvn -q test. The build must declare JUnit Jupiter 5.9.3 (test scope) and Maven Surefire 3.1.2 with useModulePath=false.
