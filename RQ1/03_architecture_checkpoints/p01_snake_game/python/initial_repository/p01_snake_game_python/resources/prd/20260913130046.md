## Domain Reasoning

- Core entities: Direction (Enum with exact integer deltas), Position (immutable, hashable), Grid (validated bounds), Snake (mutable body, direction, movement), Food placement via RandomProvider, and Game (state orchestration).
- Movement derives strictly from Direction.delta; immediate reversal is rejected via Direction.is_opposite and Snake.turn() rules.
- Collision logic checks walls and self collision using explicit Position/Grid/body parameters (no direction-to-delta duplication). Moving into the departing tail is safe when not growing.
- Food is consumed if the next head equals food position; then growth occurs and score increments exactly once. New food is placed only after consumption.
- Game.step computes next_head once, validates collisions before mutation, advances snake, updates score and food deterministically based on RandomProvider.
- Game.state returns a flat schema: width, height, snake (list of (x, y)), food (x, y), score, over, direction (enum name string).
- Randomness is abstracted via RandomProvider to ensure deterministic tests and a predictable Main.py demo.
- Reset reinitializes the game to a live state without requiring a second mandatory init call.

## Domain Expectations

- Direction Enum in snake_game/direction.py owns delta() -> (dx, dy) and is_opposite() rules; no other module duplicates these deltas.
- Grid and Position in snake_game/grid.py: Position is immutable/hashable; Grid validates width/height; Grid never imports Direction.
- Snake in snake_game/snake.py: turn(requested) -> bool rejects immediate reversal; next_head() uses direction.delta(); advance(grow: bool) mutates body in place.
- Collision module operates only with Position/Grid/body arguments and checks wall and self collision; departing tail safety when not growing.
- Food placement uses grid bounds and RandomProvider; avoids placing on the snake body; only placed after consumption.
- Game constructor initializes live state with given grid, rng, start, direction; exposes turn, step, reset, state, is_over, score_get APIs.
- Main.py provides deterministic demo, at most two safe steps, prints one snapshot, exits under __name__ guard.
- Tests include exact deterministic fixtures: no-growth and growth, with precise positions, scores, and over flags.
