## Implementation approach

Protocol-preserving, deterministic Python 3.10 architecture for Custom press releases. We keep Main.py thin and isolate all reusable domain logic under a lowercase snake_case package press_releases. The import graph is acyclic and dependency-ordered: errors.py -> types.py -> template.py -> validation.py -> press_release.py -> search.py -> __init__.py -> Main.py -> tests/test_main.py. We implement exactly the 10 required files, avoid extra modules, and prohibit datetime/time/random/uuid/pathlib/os/threading or any clock abstractions. Only pytest is declared in requirements.txt. The domain model follows strict rules: PressRelease is a mutable class (no dataclass), value objects Contact, VersionEntry, and Template are frozen dataclasses with only generated initializers and no custom __init__. Template.render uses exactly a literal sorted key replacement loop and leaves missing placeholders unchanged. Validation returns booleans rather than throwing; constructor of PressRelease never validates. Lifecycle transitions enforce DRAFT -> REVIEW -> PUBLISHED with guards and domain-specific exceptions (DomainError, InvalidTransitionError). Version history appends exactly VersionEntry(number=1, rendered_text) on first publish. Tags are trimmed, non-blank, unique, insertion-ordered. Search preserves input order, ignores None entries, uses exact normalized tag matching (trim-based), and case-insensitive text search for headline/body. __init__.py re-exports only canonical names and never mentions run_demo. Main.run_demo performs a non-interactive demo up to PUBLISHED and prints at most one concise line under __name__ guard. Tests are deterministic and headless, import run_demo from Main in a separate literal line, import all other symbols from press_releases, and include exactly three concise cases covering demo to PUBLISHED, rendering/validation/lifecycle/version-history, and invalid-candidate/transition error/tags/search. Implementation Tasks are ordered strictly by dependencies so later files import earlier ones without cycles.

## Program call flow

sequenceDiagram
    participant T as Template
    participant C as Contact
    participant PR as PressRelease
    participant S as search_by_tag
    participant ST as search_text

    M->>T: create Template(name, content)
    M->>C: create Contact(name, email)
    M->>PR: create PressRelease(id, headline, body, contact, template, custom_fields)
    M->>PR: validate()
    alt valid
        M->>PR: add_tag("media")
        M->>PR: submit_for_review()
        M->>PR: publish()
        PR->>PR: render_plain_text() -> Template.render(fields)
        PR->>PR: version_history() append VersionEntry(1, rendered)
    else invalid
        PR-->>M: validate() returns False
        M->>PR: submit_for_review() raises DomainError
    end
    M->>S: search_by_tag([PR], "media")
    M->>ST: search_text([PR], "hello")
    M-->>M: return dict with release, state, versions, rendered_text
