## Domain Reasoning

- Entities: Player (X, O), Board (square grid of size>=5), Move (row, col, player, move index), GameState (Status IN_PROGRESS, DRAW, X_WON, O_WON with optional winner), Game (state machine), WinDetector (pure logic)
- Game API is exactly: Game(int size), Board getBoard(), Player getCurrentPlayer(), GameState getState(), boolean placeMove(int row,int col), boolean undo(), void reset(), java.util.List<Move> getHistory()
- X-first rule: Game(int size) rejects size<5, and every new or reset game starts with Player.X
- Toggle-only-while-in-progress rule: placeMove advances currentPlayer to next only when resulting state remains IN_PROGRESS; after a win currentPlayer remains the winner
- Move validation: while IN_PROGRESS, out-of-bounds or occupied cells return false with no mutation; when terminal (DRAW, X_WON, O_WON) every placeMove returns false with no mutation
- Undo semantics: undo returns false with no mutation when history empty; otherwise remove latest move, clear that board cell, restore currentPlayer to removed move's player, restore GameState.inProgress(), return true
- Reset semantics: reset clears every board cell and history, restores currentPlayer=Player.X and GameState.inProgress(); never derive first player from pre-reset turn
- Win detection: WinDetector.hasFiveInRow(Board,int,int,Player) counts the just-played stone plus matching stones in both signs of exactly (0,1), (1,0), (1,1), and (1,-1). Five or more contiguous stones wins immediately
- Draw detection: when the board has no empty cells and there is no win, state becomes DRAW
- Tests focus on one exact nine-move horizontal win sequence (7,3),(0,0),(7,4),(0,2),(7,5),(0,4),(7,6),(0,6),(7,7) and a state fixture that mentions both placeMove(1,1) and placeMove(2,2). Exactly three tests

## Domain Expectations

- Two-player alternation with Player.X starting on new or reset game
- Legal move validation prevents placing on occupied or out-of-bounds cells and prevents any mutation when the game is terminal
- Five-in-a-row detection in four directions with two-sided counts: (0,1), (1,0), (1,1), (1,-1)
- Board state supports snapshot deep copy, clearCell agrees with empty-cell representation, isEmpty consistent across methods
- Undo restores previous turn and clears the exact last cell; reset clears the board and history and sets turn to X
- Draw state occurs when the board is full and no win is present
- History is append-only for successful moves, removable only by undo; getHistory returns an unmodifiable copy or view
- Main.main provides a minimal demonstration and returns normally without System.exit

- As a player, I want to place stones on a square board and have turns alternate automatically while the game is IN_PROGRESS

- As a player, I want to reset the game to start a new match with Player.X and an empty board
- As a player, I want invalid moves (out-of-bounds or occupied) to be rejected without changing the state
