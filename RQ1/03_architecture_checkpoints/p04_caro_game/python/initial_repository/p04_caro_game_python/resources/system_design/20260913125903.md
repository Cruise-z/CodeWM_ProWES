## Implementation approach

Preserve protocol files exactly: requirements.txt, Main.py, and tests/test_main.py. Keep Main.py thin and deterministic: construct a CaroGame, execute the exact nine-move canonical sequence, print once, and exit. Place reusable, pure domain logic under a lowercase snake_case package named 'caro'. Maintain an acyclic import graph: foundational types and errors must not import engines or entrypoints; rules remain pure and separate; the engine (CaroGame) orchestrates board updates and state transitions. Python 3.10 conventions only. Tests remain headless and deterministic: they import the package and Main.py, verify core behaviors (validation precedence, canonical nine-move horizontal win, reset behavior, and error paths) using pytest and explicit exception imports, without any UI or I/O dependencies.

## Program call flow

sequenceDiagram
    participant M as Main.py
    participant G as CaroGame
    participant B as Board
    participant R as Rules
    M->>G: construct(size=15, first_player=X)
    loop Canonical nine-move sequence
        M->>G: move(row,col)
        G->>G: validate status IN_PROGRESS else raise GameOverError
        G->>B: in_bounds(row,col)? else InvalidMoveError
        G->>B: is_empty(row,col)? else InvalidMoveError
        G->>B: set_cell(row,col,current_player)
        G->>R: has_five_or_more(B,row,col,current_player)?
        alt win
            G->>G: set status to X_WON/O_WON; set winner; do not toggle
        else no win
            G->>B: is_full()? draw if true
            G->>G: toggle player if still IN_PROGRESS
        end
    end
    M->>M: print single status line and exit
