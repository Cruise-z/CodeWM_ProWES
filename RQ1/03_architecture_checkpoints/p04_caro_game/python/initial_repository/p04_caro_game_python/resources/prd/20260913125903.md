- Automated, deterministic, no manual interaction, no GUI rendering, no network, no OS-specific behavior

- Cover runtime wiring via Main.py and representative core rules: validation precedence, canonical nine-move horizontal win sequence, reset behavior, and error paths

## Domain Reasoning

- Core Entities: CaroGame as the public API, Board representation (e.g., 15x15 grid), Cell states (EMPTY, X, O), Move history entries
- State Machine: statuses IN_PROGRESS, X_WON, O_WON, DRAW with transitions driven solely by CaroGame.move(row, col) and reset()
- Turn Handling: two players X and O alternate; CaroGame.move has no player argument and always places the current player’s stone
- Validation Precedence: if status is not IN_PROGRESS, raise GameOverError before any other validation; otherwise validate bounds and occupancy; invalid bounds or occupied raise InvalidMoveError and must not change board, turn, history, status, or winner
- Win Detection: freestyle Gomoku semantics—five or more contiguous stones wins immediately; has_five_or_more must compute 1 + counts in both signs for each of exactly (0,1), (1,0), (1,1), and (1,-1)
- Draw Detection: when the board is full, no winner exists, and status changes to DRAW
- History/Reset: every legal move appends exactly one Move and toggles player only if the resulting state remains IN_PROGRESS; reset recreates an empty board of the same size, clears history/winner, restores IN_PROGRESS, and restores the constructor’s first player
- Canonical Demonstration: the exact nine-move sequence X:(7,3), O:(0,0), X:(7,4), O:(0,2), X:(7,5), O:(0,4), X:(7,6), O:(0,6), X:(7,7) must produce X win on the ninth move and no earlier move forms five; runtime demo and tests must stop immediately after the ninth move

## Domain Expectations

- A CaroGame object exposes move(row, col), reset(), getters for board, current_player, status, winner, and move history
- Legal move validation enforces: game not over -> in-bounds -> unoccupied, in that exact precedence
- Alternating turns occur only after a legal move that leaves the game IN_PROGRESS
- Win detection uses five-or-more contiguous stones in any of the four principal directions
- Draw is declared when all cells are filled with no winner
- Move history records the exact order of moves placed by alternating players
- Reset fully restores the initial state: empty board, first player, cleared winner and history, status IN_PROGRESS
- Runtime demo executes the canonical nine-move horizontal win sequence and prints once before exiting

## User Stories

- As a player, I can place a stone on my turn without specifying my identity; the game tracks whose turn it is
- As a player, I receive a clear error if I try to move after the game is over (GameOverError)
- As a player, I receive a clear error if I try to place a stone out-of-bounds or on an occupied cell (InvalidMoveError) and the game state does not change
- As a player, I want the game to detect five-or-more in a row immediately in all four principal directions
- As a player, I can reset the game to the initial state with the same board size and first player
